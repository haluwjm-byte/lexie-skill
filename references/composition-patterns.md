# 构图模式与原创规则

## 基础结构类型

每张只选一种主结构。

### Workflow 流程

适合输入 → 处理 → 输出、内容生产、AI 工作流和自动化链路。左侧输入，中间由 Lexie 或怪机器处理，右侧输出；橙色箭头表示主流向。

### 系统局部

适合信息来源、过滤器、数据库、渲染器或 agent 系统局部。只画 3–5 个核心模块，Lexie 操作其中一个关键部件。

### 前后对比

适合混乱/有序、手动/自动、分散/收拢、焦虑/稳定。左右对比，中间用简洁动作或箭头连接；Lexie 负责把左侧状态变成右侧状态。

### 角色状态

适合用户痛点、创作者状态、工具太多、信息焦虑、卡住到跑起来。用 2–4 个 Lexie 连续状态，每个只配一个短标注；保证角色外形一致。

### 概念隐喻

适合内容工厂、信息仓库、脑内黑盒、工作流机器和自动日报。用一个怪物件或低科技机器，少量输入，一个输出；Lexie 操作关键部位。

### 方法分层

适合方法论框架、系统层级、能力栈和内容系统分层。使用不规整盒子或手搭结构，Lexie 搬砖、扶梯、装配或贴标签；不要正式金字塔。

### 地图路线

适合从想法到上线、用户路径、内容承接和学习路线。使用一条弯曲路径和少量节点，Lexie 牵线、修桥、开门或推车。

### 小漫画分镜

适合失败到成功、真实过程、吐槽和使用前后变化。使用 2–4 个小场景，每格只表达一个动作；每格都是同一个 Lexie。

## 原创隐喻生成法

1. 把抽象概念换成物理动作：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. 把系统结构换成低科技物件：旧机器、纸箱、抽屉、水管、邮筒、怪表盘、秤、井、梯子、线团或怪工位。
3. 让 Lexie 亲自承担动作：钻进机器修补、拉错线、守门、搬运、称重、扶梯子、记录或把东西塞进怪装置。

物件只选 1–2 个，不要堆满。动作必须服务核心意思。

## 反复刻规则

不要默认复用旧小黑案例中的构图，包括传送带断点、拉判断杆、角色变漏斗、切素材鱼、牵承接路径、拉三层信息源、拿喇叭/搭桥/开门、盖章工具箱或举牌看坑。

同类主题也要换新隐喻。例如“承接路径”可以画 Lexie 把内容尾巴接到门把手；“一鱼多吃”可以改为把一个纸团压成几种形状。角色换成 Lexie 不等于构图已经原创。
